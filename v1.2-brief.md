# TriageHub v1.2 — Brief operativo per Claude Code

> **Leggi prima `AGENTS.md`** per la filosofia generale del progetto, poi questo file per la spec della v1.2.
>
> Questo brief è prescrittivo sulle decisioni di prodotto, libero sulle scelte di implementazione fine. Quando hai dubbi tra due strade equivalenti, scegli quella più allineata alla filosofia "vanilla, single-file, privacy-first" di `AGENTS.md`.

---

## Obiettivo della v1.2 in una frase

Trasformare TriageHub da app con **un solo flusso attivo** in app con **flussi paralleli indipendenti** (Workspace), gestiti tramite una galleria template **flottante draggabile** e uno switcher **a cards** sopra la lista item.

---

## Perché

Un utente reale non triagia "una sola cosa": gestisce in parallelo le sue email, i suoi lead commerciali, il suo listino prodotti. Nella v1.1 attivare un nuovo template sostituiva gli stati e rendeva l'app monouso. La v1.2 risolve.

---

## Decisione architetturale: Workspace come container indipendenti

Ogni Workspace è un container che ha i suoi:
- `items[]` (gli item triagiati)
- `categories[]` (le categorie del workspace)
- `statuses[3]` (i 3 stati custom del workspace)
- `itemStatus{}` (mappa item→stato)
- `valueUnit` (unità del campo numerico, es. €, pcs, score)

I Workspace sono indipendenti tra loro. Cambiare workspace = cambiare tutto. La firma "3 stati" di TriageHub resta, ma è 3 stati **per workspace**, non 3 stati globali.

## Migration v1.1 → v1.2 (CRITICA)

Gli utenti che hanno già usato la v1.1 hanno dati nel vecchio formato. **Devi migrare automaticamente al primo caricamento**, senza far perdere nulla.

```js
function loadState() {
  const saved = JSON.parse(localStorage.getItem(STORAGE_KEY) || '{}');
  
  // Caso 1: dati v1.1 (hanno "items" al top level, niente "workspaces")
  if (saved.items && !saved.workspaces) {
    const wsId = 'ws_' + uid();
    state = {
      workspaces: {
        [wsId]: {
          id: wsId,
          name: currentLang === 'it' ? 'Default' : 'Default',
          emoji: '📋',
          templateId: null,
          createdAt: new Date().toISOString(),
          items: saved.items || [],
          categories: saved.categories || [],
          statuses: saved.statuses || structuredClone(DEFAULT_STATUSES),
          itemStatus: saved.itemStatus || {},
          valueUnit: saved.valueUnit || ''
        }
      },
      activeWorkspaceId: wsId,
      filter: { search: '', cat: 'all', status: 'all' },
      ui: { galleryOpen: false, galleryPos: { x: null, y: null }, galleryCollapsed: false }
    };
    saveState();
    toast(t('migratedToV12'));  // "✓ I tuoi dati sono stati migrati al nuovo formato Workspace"
    return;
  }
  
  // Caso 2: dati v1.2 già presenti
  if (saved.workspaces) {
    state = saved;
    return;
  }
  
  // Caso 3: niente dati (primo avvio)
  state = { workspaces: {}, activeWorkspaceId: null, filter: {...}, ui: {...} };
}
```

**Test obbligatorio prima del commit:** apri la versione v1.1 in una tab, crea qualche item, ricarica la v1.2 nella stessa origine, verifica che gli item siano ancora lì in un workspace "Default".

## UX Spec — Galleria template flottante draggabile

### Comportamento

- **Posizione iniziale**: top-right, 24px dal bordo, sotto la toolbar (non la deve coprire). Persisti `ui.galleryPos` in localStorage dopo ogni drag.
- **Sempre visibile** quando `ui.galleryOpen === true`. Il pulsante "✨ Template" in toolbar la apre/chiude (toggle).
- **Header draggabile**: tutta la fascia superiore (titolo + bottone collapse + bottone close) è il "drag handle". Click & drag con il mouse muove la finestra. NON usare librerie esterne — vanilla JS con `mousedown`/`mousemove`/`mouseup` su `window`.
- **Bottone collapse** (─): la finestra si riduce a una pillola compatta che mostra solo l'emoji ✨ + "Template (7)". Click sulla pillola riespande.
- **Bottone close** (×): chiude la galleria. Si riapre dal pulsante in toolbar.
- **Z-index**: superiore alla toolbar ma inferiore ai dialog modali. Suggerimento: `z-index: 80` (toolbar è 50, dialog 100+).

### Aspetto

- Larghezza fissa **300px** desktop. Background `var(--card)`, border, border-radius 16px, shadow `var(--shadow-lg)`.
- Header: 14px padding, font-family serif italica per il titolo "Template", border-bottom subtile.
- Body: 7 cards (Vuoto + 6 template) in **una colonna** (non grid 3-colonne come oggi). Card più compatta: emoji 22px + nome serif 18px + desc 1 riga.

### Stato dei template

Ogni card della galleria ha **3 possibili stati visivi**:

1. **Disponibile** (workspace con quel `templateId` non esiste): card normale, hover azzurro, click → crea workspace nuovo e attivalo. Toast: `✓ Workspace "Email" creato`.

2. **Attivo** (workspace con quel `templateId` esiste ed è quello corrente): card con bordo accent, badge "● Attivo" in alto a destra, click non fa nulla (è già lì). Aggiungi `pointer-events: none` solo al bottone, non alla card così l'utente vede l'hover.

3. **Già creato non attivo** (workspace esiste ma è un altro quello corrente): card con badge "↗ Vai", click → switcha al workspace esistente (NON ne crea uno nuovo). Toast: `✓ Sei nel workspace "Email"`.

**Edge case:** se l'utente clicca "Vuoto" più volte, crea workspace "Vuoto 1", "Vuoto 2", "Vuoto 3"... (numerazione automatica solo per Vuoto, gli altri template hanno workspace unico).

### Mobile (viewport < 768px)

La finestra flottante non può stare "a lato" su mobile. Comportamento:

- Quando viewport < 768px, la galleria diventa **bottom sheet**: ancora flottante, ma posizionata in basso, larghezza piena, max-height 60vh, swipe-down per chiudere (o click su ×).
- Il drag handle desktop diventa un piccolo "grabber" stile iOS in cima.
- Al resize della viewport (oltre 768px) torna a finestra flottante in alto a destra.

## UX Spec — Workspace cards switcher

Sopra la search-row, una nuova riga con le **cards dei workspace attivi**.

### Aspetto desktop

```
┌──────────────┐  ┌──────────────┐  ┌──────────────┐  ┌─────┐
│ 📧 Email     │  │ 💼 Lead      │  │ 📦 Listino   │  │  +  │
│ 12 item      │  │ 47 item      │  │ 350 item     │  │     │
│ ⭐ 3 ⏳ 5 📦 4 │  │ 🔥 8 ☀️ 20...│  │ 🚀 50 🔍 ...│  │     │
└──────────────┘  └──────────────┘  └──────────────┘  └─────┘
   ATTIVO            inattivo           inattivo       new
```

- Card 180px × 90px, border-radius 14px, padding 14px.
- **Workspace attivo**: border 2px accent, leggera elevation, sfondo card normale.
- **Workspace inattivo**: border standard, sfondo `var(--bg)` leggermente smorzato, hover diventa cliccabile.
- **Bottone "+"**: apre la galleria (alias del pulsante "Template" in toolbar).
- Mostrano: emoji + nome (serif italica), count totale item, mini-stats con i 3 stati ed emoji.
- **Right-click / long-press / tasto ⋮** sulla card apre menu contestuale: *Rinomina*, *Cambia emoji*, *Esporta solo questo*, *Elimina workspace* (con conferma esplicita).

### Aspetto mobile

Le cards si scrollano orizzontalmente (overflow-x: auto, scrollbar nascosta), tutte 160px di larghezza. Snap scroll per allineare al bordo.

### Eliminare un workspace

- Conferma esplicita con preview: "Eliminare il workspace **Email**? Contiene **12 item** che andranno persi. L'azione non è reversibile."
- Bottone "Esporta prima" in modal di conferma → scarica il JSON solo di quel workspace, poi chiede di nuovo conferma.
- Se l'utente elimina l'unico workspace, ne viene creato uno vuoto "Default" automaticamente (l'app non resta mai senza workspace).

## Criteri di accettazione (test list)

Prima di considerare la v1.2 fatta, **devono passare tutti questi**:

### Funzionali
1. Apro l'app per la prima volta → galleria flottante visibile, nessun workspace.
2. Clicco "📧 Email" → si crea il workspace, diventa attivo, galleria mostra "Attivo" su Email.
3. Clicco "💼 Lead" → si crea il secondo workspace, diventa attivo, Email diventa "↗ Vai".
4. Sopra la lista vedo 2 cards (Email, Lead). Lead ha bordo accent.
5. Click su card Email → diventa attivo. Galleria si aggiorna.
6. Aggiungo 3 item su Email, switch a Lead, aggiungo 2 item, switch a Email → vedo i miei 3.
7. Click destro su Lead → menu contestuale → Rinomina → "Lead Q4" → cards si aggiornano.
8. Elimina workspace Email → conferma → resto solo con Lead Q4.
9. Elimina ultimo workspace → app crea automaticamente "Default" vuoto.
10. Drag galleria → posizione persiste al refresh.
11. Collassa galleria → pillola compatta. Click → riapre nello stesso punto.
12. Resize finestra a 600px → galleria diventa bottom sheet.
13. Resize a 1200px → torna a finestra flottante in alto a destra.
14. Export JSON → file include tutti i workspace.
15. Import JSON da v1.1 → migra come "Default" workspace.
16. Reset totale → conferma doppia → svuota tutto, app come al primo avvio.

### Migration
17. Apri la v1.1 (puoi fare un revert di test su un branch), crea 5 item, switcha a v1.2 sul branch main → al refresh i 5 item sono nel workspace "Default".
18. Esporta backup JSON dalla v1.1, importa in v1.2 fresh → finisce come workspace "Default".

### UX
19. Tutti i toast usano la stringa giusta in IT e EN.
20. Tab key navigabile su tutti i nuovi controlli (a11y).
21. Niente layout shift quando cambi workspace.
22. Galleria flottante non copre mai la search-input (z-index e posizionamento).
23. Drag della galleria non triggera il click sui template card (separa correttamente i due eventi).

## Cosa NON fare in questa v1.2

Per non perdere il focus, **rimanda a v1.3**:
- Drag & drop reorder degli item dentro un workspace
- Custom fields oltre `value` (numerico)
- Workspace template marketplace (utenti che pubblicano i propri template)
- Sync cloud (la promessa privacy resta!)
- IndexedDB per dataset > 5k item per workspace

## In caso di dubbi

Se qualche scelta UX o tecnica ti sembra ambigua, **scegli la via più semplice e leggera**, coerente con la filosofia di `AGENTS.md`. Meglio una v1.2 minimale e funzionante oggi che una v1.2 perfetta tra due settimane.
